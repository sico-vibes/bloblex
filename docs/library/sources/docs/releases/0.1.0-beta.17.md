# Bloblex 0.1.0-beta.17

## Changes

- **OpenCode recovery:** fix a false failed-protocol check on OpenCode 1.18.35. Its successful ACP help is written to stderr, which Bloblex previously discarded. Both output streams are now checked with bounded retention and the existing timeout, exit-status and protocol validation. Update Bloblex, then use Settings → Agents → Scan again if an old warning remains; OpenCode does not need reinstalling for this particular failure.
- **CLI health:** blobs attached to a failed coding-agent runtime show an error expression and a red indicator beside their name, with safe problem details and recovery guidance. Their messaging controls are disabled until recovery. Other coding agents remain usable, and the companion follows the same state.
- **Message actions:** the experimental Message actions setting now reveals three controls beside user and assistant bubbles on hover or keyboard focus: Reaction, Reply and Copy. Copy copies the message text. Retry and Edit remain in the user-message context menu.
- **Reactions:** choose from six emojis and toggle your saved reaction. Reactions persist across app restarts; no bot reactions or invented counts are added.
- **Quoted replies:** select a message to stage a cancellable quote in the composer. The daemon resolves the original message and sends its bounded excerpt as context alongside your new text. History retains the reference and original messages. Read-only side conversations remain read-only.
- **Usage tips:** a separate experimental switch, off by default, adds dismissible notices above the composer for the selected coding agent's reported high usage. Unknown, unavailable, stale or expired windows do not produce notices. Dismissals respect the actual window period and warning threshold; no upgrade destination or price is invented.
- **Usage layout:** the wider Detailed Usage popover keeps OpenCode's session, weekly and monthly percentages on one stats line at desktop widths, with all three windows retained.
- **Codex activity:** stream bounded command output and show reported MCP/dynamic tool inputs, results, progress and status. Details are normalized before reaching the UI. Older steps can only show the information originally saved.
- **Codex models and effort:** use the reported wire values for each model, with display labels Light, Medium, High, Extra High, Max and Ultra. Luna models stop at Max; Ultra appears only where the live catalog offers it. GPT families sort numerically newest to oldest, while other coding agents retain their existing grouping.
- **Character effects:** empty-chat characters have extra raster space above their body for sleeping Zs and other upward effects, preserving body size, position and interaction bounds.

Message actions, usage tips and the other experimental controls can be disabled in Settings → General → Experimental.

## Verification

- Independently passed: desktop typecheck, all 426 desktop tests, production web build, all 306 Rust workspace tests excluding the desktop crate, native desktop library compile check, and the Windows x64 NSIS bundle.
- Independent OpenCode QA and root source review found model-ordering and usage-notice edge cases; these were corrected and covered by regressions before release.
- Read-only host checks confirmed OpenCode's ACP handshake and Codex 0.161.0's model catalog. The built beta.17 daemon, using an isolated temporary database, reported Claude, Codex and OpenCode 1.18.35 as protocol-healthy. No coding prompt was sent through this daemon check, and its private database was removed.
- Browser fixtures verified exact copied text, adjacent message actions, visible reaction badges, quoted-draft placement and sent-history links, usage-notice dismissal, OpenCode's three metrics sharing one line, and per-runtime error presentation with other CLIs remaining usable. Dark and light views and the 1000px minimum desktop width were inspected; an empty-state sleeping Z was visibly unclipped.
- Codex display names follow the [official model controls](https://learn.chatgpt.com/docs/agent-configuration/subagents); offered wire values remain attached to each model from the CLI catalog.

Live coding turns through the installed Bloblex app, real Windows taskbar/tray behavior and clean-machine installation remain unverified.
