## Earlier notes

Bloblex reuses the MIT-licensed Windows implementation of [Coucou](https://github.com/Louis-CFM/coucou/tree/8e12bed56134d2ee7165e73f132646b143ce56e4), pinned to commit `8e12bed56134d2ee7165e73f132646b143ce56e4` (1 October 2026). The vendored upstream files are `apps/desktop/src/blob/coucou/island/fsm.ts` (FSM, unchanged), `apps/desktop/src/blob/coucou/core/anim.ts` (animation primitives, unchanged), and the rounded-corner/layout constants excerpt in `apps/desktop/src/blob/coucou/core/layout.ts`. The original files are [`fsm.ts`](https://raw.githubusercontent.com/Louis-CFM/coucou/8e12bed56134d2ee7165e73f132646b143ce56e4/windows/src/island/fsm.ts), [`anim.ts`](https://raw.githubusercontent.com/Louis-CFM/coucou/8e12bed56134d2ee7165e73f132646b143ce56e4/windows/src/core/anim.ts), and [`layout.ts`](https://raw.githubusercontent.com/Louis-CFM/coucou/8e12bed56134d2ee7165e73f132646b143ce56e4/windows/src/core/layout.ts). Upstream's project-specific palette, assets, upload views, and app shell are excluded. The upstream license is [MIT](https://github.com/Louis-CFM/coucou/blob/8e12bed56134d2ee7165e73f132646b143ce56e4/LICENSE), reproduced in [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

The adaptation follows Coucou's hidden → compact (`petit`) → expanded (`home`) flow, hover gaze, 0.5-second / 0.72-damped spring response, 340 ms collapse curve, click squash, and three-poke dizzy reaction. `apps/desktop/src/blob/coucou/core/anim.ts` vendors the upstream generic `Ease`, `Spring`, `Tracked`, and close-curve primitives from `windows/src/core/anim.ts` unchanged at the pinned commit (header comments only). `apps/desktop/src/blob/coucou/island/fsm.ts` vendors the interaction state machine; Bloblex wraps it in its own companion FSM adapter.

The launch animation is a pose-level adaptation of `windows/src/mochi/greeting.ts`, not a copy of its canvas renderer. The pinned source SHA-256 is `F49BA11B04F620B8A289F92F1875D4CF92845544C18A452BCA187C42DB18C367`; the vendored `anim.ts` source SHA-256 is `3C1A3354050F7D276EF7A347A72F6C4EE6A09B8A0A7C84DE9CB8D818D25CA334` and the local file including provenance header is `2150F8CBE3683855EB8D10BDB509800293E4E8F33EED6A91D1005C99AB3CCE0C`. In `motion.ts`, the pose adapter retains source `T` landmarks and maps `hb = lerp(3, 58, E.back(seg(t, .02, .45)))`, source y travel 16→90, dip scale `sx=1+.04k` / `sy=1-.06k`, pop oscillation, eye type/open/roll, gaze, staggered handL/handR reveal and tuck, 2.5 Hz wave, badge back-ease, halo, and tint. The launch module uses greeting.ts's own back curve constant 1.70158; generic spring/interaction animation remains the separately vendored core curve. It preserves the 4.6-second total and sample points: happy squint 0.60–0.82s; dip/pop 1.25–1.52s; first blink at 1.95s; content eyes 2.45–2.58s; asymmetric appendage tuck 2.58–2.8s; badge entry 2.72s; settle 2.85–3.2s; second blink 3.8s; tint 3.85–4.15s. Bloblex maps source body position/scale, eye type/opening, gaze, appendage pose, badge, halo, and tint onto its own circular body. The appendages remain a low round dot and a raised tilted oval; there are no arms, fingers, or mouth. `BlobCanvas.tsx` keeps the Bloblex palette and procedural dots/halo. No Coucou/Mochi character art, sound, or other media is copied.

Eye placement uses the source's normalized geometry: base spacing `±0.19 × bodyHeight`, horizontal look `lookX × (1.34 × halfHeight) × 0.42`, and vertical position `0.12 × halfHeight + lookY × 0.28 × halfHeight + eyeRoll × 1.25 × halfHeight`; positive vertical gaze remains downward in canvas coordinates. A pure coordinate test guards the sign and scale. The greeting canvas uses a wider 1.85× width and 1.5× height so the full left-dot/right-oval pose remains visible through the wave. The three-poke dizzy reaction uses a deadline outside the canvas effect so reduced-motion mode and renderer cleanup do not strand the recovery notification; canvas teardown is side-effect-free, avoiding false FSM completion during React StrictMode effect replay.

The shell wraps the upstream FSM in `apps/desktop/src/blob/companionFsm.ts`. It preserves the source `hidden`, `petit`, `home`, and `coucou` transitions, including 15-second home collapse, 600 ms greeting-completion collapse, and 10-second hovered-greeting timeout. The adapter cancels the upstream 60-second compact auto-hide because a freely placed window must remain recoverable at its saved desktop position; users can explicitly hide it from companion settings. Approval pinning is the adapter's other FSM extension: ordinary navigation preserves the pin, and resolving permission explicitly releases it.

`apps/desktop/src/blob/companionLayout.ts` is a thin shell adapter over source `COMPACT_W=288`, `EXPANDED_W=640`, `ROUNDED_CORNER=14`, `EXPANDED_CORNER=22`, overview content height 160, and greeting height 150. The Tauri window adds Bloblex controls and avatar space, yielding 344×62 compact, 640×196 greeting, and 640×226 overview logical-pixel bounds. It remains bottom anchored while it grows and is freely draggable. The companion shell uses Coucou's rounded-corner values on all four edges, never a pill/stadium radius.

Bloblex intentionally changes placement and visibility: the companion is a bottom-center floating bill, freely draggable and position-persistent, rather than Coucou's top-edge notch. It stays visible in a minimal compact state until explicitly hidden so it cannot disappear into an unknown screen location. Clicking the character opens compact controls; Open Bloblex is a separate action in the expanded panel. Approval stays expanded until resolved. Reduced-motion mode snaps the character and capsule to their target states. Bloblex uses its own circular character drawing, palette, expressions, and UI; no Coucou/Mochi character art or other media is copied.

## Activity and local file-reference behavior

The canvas now applies restrained thinking gaze drift and a small rhythmic body pulse for `working`, `tool_activity`, and `file_activity`; all of these are disabled under reduced motion and stop when the page is hidden or the canvas is not intersecting. The same production draw loop uses the activity helper. Error and local-reference error moods use the longer, slower blink cadence. This is an adaptation of the pinned engine's state-specific gaze, blink, and movement behavior; it does not pretend to reproduce provider internals or tool progress.

The current UI status adapter in `apps/desktop/src/ui/companionStatus.ts` feeds the canvas as follows:

| UI/runtime state | Character behavior | Coverage |
|---|---|---|
| idle / online | breathing, randomized blink, online dot | Implemented |
| composing / listening | focused expression and forward lean | Implemented |
| thinking | source-inspired focus with subtle eye drift | Implemented |
| working / tool activity / file activity | restrained body rhythm; actual tool/file event badge | Implemented |
| permission | alert expression and pulse; shell approval pin remains outside canvas | Implemented |
| success | one hop and brief sparks | Implemented |
| error | droop, downward gaze, annoyed eyes, slower blink | Implemented |
| rate limited / sleeping | sleepy eyes, dim palette and low breathing cadence | Implemented |
| budget warning | warning badge/ring pulse | Implemented |
| hover / poke | cursor gaze, squash, and three-poke dizzy/recovery | Implemented |
| file reference drop / preparing / ready / sending / error | receive cue, activity dots during actual inspection, paperclip, static send cue, or error | Implemented across canvas and desktop |

The status adapter prioritizes daemon/runtime offline, pending permission, budget warning, rate limit, and provider failures before ordinary activity. A new user interaction or explicit local-file action can replace a stale completed-success cue; active safety and failure states still take precedence. Canvas rendering is isolated from provider I/O and follows document visibility, intersection, and reduced-motion settings.

`BlobCanvas` accepts `fileStage?: 'drop' | 'preparing' | 'ready' | 'sending' | 'error'`, mapped to `file_drop`, `file_preparing`, `file_ready`, `file_sending`, and `file_error`. Drop is a gentle receive cue, preparing shows activity dots only while a real local inspection runs, ready shows a local-reference glyph, sending shows a static outbound cue, and error has a droop/slow blink. The normal activity state `file_activity` remains reserved for actual normalized runtime file events. Offline, permission, budget warning, rate limit, and provider success/error moods take precedence over the file cue. Desktop wires these stages from the companion's actual local-file state.

Coucou's pinned [`island.ts`](https://raw.githubusercontent.com/Louis-CFM/coucou/8e12bed56134d2ee7165e73f132646b143ce56e4/windows/src/island/island.ts) implements inbox ingestion and timed upload progress. Bloblex does not reuse that flow: the native `inspect_local_file` implementation canonicalizes the selected path, checks it is a file that can be opened, and returns only file name and size. That is local metadata preparation; it does not read or copy file contents. The UI labels it a local file reference and includes it only after explicit send. The preparing cue is wired around this inspection call, with no upload progress or implied completion. The Windows native unit tests cover valid regular files (including spaces and non-ASCII names), missing paths, directories, and an exclusive-share unreadable-file case; `cargo test -p bloblex-desktop --lib` passed 4/4 on Windows. Those tests validate metadata inspection only, not the full drag/drop UI flow or provider-side file access. No completion cue is emitted merely because a path was selected or a prompt was accepted.

## Optional original sound cues

`apps/desktop/src/blob/soundCues.ts` synthesizes short sine-wave phrases locally; it copies no Coucou audio or other sound asset. The persisted `companion.soundsEnabled` preference defaults to off. Hydrating the preference does not create an audio context or play anything; enabling requires a direct user gesture to unlock browser audio. Welcome is emitted once at the logical greeting start, poke on character pointer input, approval when a pending permission first appears, and completion/error on a terminal mood transition. Muting, reduced motion, hidden documents, unsupported audio contexts, and construction/resume failures silence or suppress cues. The mounted Canvas tests guard welcome/poke against StrictMode replay, while sound-module unit tests use a mocked AudioContext and do not play audio. App-level cue routing is production-wired; its component transitions are not yet covered by a mounted App test.
