# Bloblex 0.1.0-beta.27

OpenCode 2 usage and sign-in, simpler dictation, model names with the provider
icon, a reworked companion mode, and chat ordering. **Verified with unit tests,
the standard gates and live runs of the OpenCode usage and sign-in code on the
machine it was built on. The dictation download dialog, the companion window and
the model pill were checked in the browser preview or by tests, not in the
installed native windows.**

## Fixed

- **OpenCode usage works with OpenCode 2 (and still with OpenCode 1).** OpenCode 2
  stores its sign-in as an OAuth login in its database, not as an API key file,
  so the Go usage lookup found no credential and showed "Unavailable". It now
  uses the stored login's access token while it is valid. Bloblex never reads the
  refresh token and does not refresh an expired one; the OpenCode CLI refreshes
  its own sign-in. Live on the build machine: the 5-hour and weekly windows came
  back.
- **OpenCode no longer shows "Sign-in status unknown".** The check no longer
  depends on the OpenCode 2 CLI, whose first call can take longer than the
  5-second limit. Bloblex reads whether a credential is stored (the credential
  database for OpenCode 2, `auth.json` for OpenCode 1; the secret itself is never
  read) and only asks the CLI when nothing is stored. Live: `Authenticated` in
  about 3 seconds.
- **"Messaged X" reads above the reply that follows it.** The model often writes
  "I asked X ..." and then calls the tool, so the notice used to land below the
  text. The notice now takes the position of its turn's text, the text moves below
  it, and the relayed answer reads below that. Open windows and a reload agree.

## Changed

- **Dictation has two engines: On device and Cloud.** The separate "ChatGPT via
  Codex sign-in" choice, the Codex sign-in row, the Permission and Withdraw rows
  and the explanatory text are gone. Choosing Cloud still asks once, in the same
  dialog (its buttons no longer overflow), before anything is sent.
- **The on-device speech model is no longer downloaded behind your back.** If
  dictation is set to this device and the model is not installed, pressing the
  microphone (or Ctrl+E) asks first, shows the size, then downloads with progress
  in that dialog and starts dictating. The cloud engine never downloads it by
  itself.
- **Dictation bubble and "Added to your message" no longer name ChatGPT or the
  cloud.** They look the same whichever engine is used. The microphone button has
  the same hover as the context ring.
- **Model names show the provider's icon, a divider, then the name** ("Sonnet 5.5",
  "Luna 6", "DeepSeek V4.1 Flash"). Claude models are grouped by family, most
  capable first (Fable, Opus, Sonnet, Haiku), newest first within each.
- **Companion mode:** the settings panel is reorganised into labelled columns
  (Sound and Chat, Teammates on the island) with a pinned footer, and the
  teammates control lists who is on the island, switches between Picked for you
  and Choose myself, and lets you tick teammates in place. There is a **volume**
  slider for companion sounds (default 80%, 0 is silent without turning sounds
  off) in the companion and in Settings. The composer controls share one aligned
  row, replies have the same bubble frame as the main chat, the collapse arrow is
  centred in its box, and `@mention` chips have a gap between the icon and name.

## Verification

- Rust workspace excluding the desktop crate: 520 tests pass;
  `cargo clippy --workspace --exclude bloblex-desktop --all-targets -- -D warnings`
  passes. The daemon tests need `RUST_MIN_STACK=33554432` on this machine, and
  the full workspace run was clean with `--test-threads=4`.
- Desktop: typecheck and 553 tests.
- Live, with the app's own code on OpenCode 2.0.28: sign-in `Authenticated`, and
  the Go usage endpoint answered with usage windows.

Known test flake (not new): `catalog_timeout_kills_the_child_and_failure_is_provider_unavailable`
can fail in a full parallel workspace run on a loaded machine (its fake process
takes longer than 10 s to start); it passes alone and with fewer test threads.

Unverified: the dictation download dialog and the companion window in the native
app, long model names in the companion composer, an expired OpenCode sign-in
(usage shows "Unavailable" until the CLI refreshes it), whether a rebuilt OpenCode
1.x install with only `auth.json` shows usage (covered by tests, not run), and
clean-machine installation.

## Manual installation

Download `Bloblex_0.1.0-beta.27_x64-setup.exe` and verify it against
`SHA256SUMS.txt`. The installer is unsigned (Windows may warn). No updater
manifest is published; the signed `channel-beta` feed remains at beta.6. Install
beta.27 manually over your current version.
