**Scope/date:** Read-only capability spike against the installed Windows npm shims on 2026-10-02. Installed versions observed: Claude Code 2.1.286, Codex CLI 0.159.3, OpenCode 1.18.34. Three authorized prompt/probe attempts were made; provider errors prevented a successful assistant answer. This is a machine-local snapshot, not a promise about later CLI releases.

## How to read this

- **CONFIRMED** means the installed CLI help/schema or a no-turn handshake directly exposed the capability. **REFUTED** means that evidence directly contradicts the plan claim. **PARTIAL** means only part of the claim is established, or provider-side application was not observable. **UNVERIFIED** means the available static evidence does not settle it.
- Evidence marked **command** is a command run in the appendix; excerpts are trimmed. **Source** names repository/package files and line ranges. Schema fields establish protocol shapes, not server acceptance or that a setting changed model behavior.

- No credential, account identifier, provider key, or private configuration value is included. Prompt text shown is synthetic and contains no user data.

## Z2. Per-adapter custom-argument allowlist proposal

Start with **no free-form extra args**. Model, effort, tier and instruction settings are typed fields owned by the adapter, so they must not be duplicated or overridden through `extra_args`. Add an argument only after a test proves it cannot alter the adapter's protocol, permission flow, working directory, or configuration source.

| Adapter | Initial allowlist | Always adapter-owned / never user-controlled |
|---|---|---|
| Claude | Empty. Future candidates may be explicitly reviewed harmless display/diagnostic switches; do not accept arbitrary option/value pairs. | `-p`/`--print`, `--input-format`, `--output-format`, `--include-hook-events`, `--permission-mode`, `--permission-prompts`, `--permission-prompt-tool`, `--dangerously-skip-permissions`, `--tools`, `--add-dir` and all `--settings`/MCP/plugin/config-file flags; `--model`, `--effort`, instruction flags; working directory (`current_dir`). |
| Codex | Empty. Typed fields go into JSON-RPC; process-level args stay fixed. | `app-server`, `--listen`/`--stdio`, `-C`/`--cd`, `--sandbox`, `-a`/`--ask-for-approval`, every danger/bypass flag, `-c`/`--config`, `-p`/`--profile`, `--strict-config`, and all config/auth/remote transport flags; cwd and thread/turn protocol payload fields. |
| OpenCode ACP | Empty. Later, `--pure` or a diagnostic log level could be considered only if it preserves stdout framing and was tested. | `acp`, `--cwd`, protocol/transport/port options, config file/env selection (including `OPENCODE_CONFIG_CONTENT`), model/mode/variant settings, permission/auto-approval settings and process working directory. Never permit `run`, `serve`, or TUI subcommands as extra args. |

Custom environment keys should be explicit per-runtime allowlisted, reject secret-looking names, and never serialize values to logs. Protect all protocol, permission, output-format, cwd, and config-file settings from custom overrides even if their current argument spellings change.

## Z3. Plan corrections before Phase 2b

- **Phase 2b / Claude:** `--append-system-prompt-file` is referenced by installed help and keeps content out of argv, but provider application and changing instructions within one stream-json process were not live-verified. The default prompt snapshot reuses initial instructions on resume and ignores changed launch prompt text. Keep snapshots and verify resume behavior before promising changed settings apply.
- **Model catalog / Claude:** the installed binary contains a worker `list_models` control request and `supportedModels`; headless `-p --input-format stream-json` support is unproven. Probe it optionally and mark static catalog data `fallback: true` when the request is absent or fails; retain custom IDs.
- **Phase 2b / Codex effort:** `thread/start`/`thread/resume` have generic `config`, not a named top-level `model_reasoning_effort`; `turn/start.effort` is the explicit per-turn field. Test whether `config.model_reasoning_effort` is accepted before relying on it.
- **Model catalog / Codex:** `model/list` exists in generated app-server schema alongside `codex debug models`; recommend `model/list` for Bloblex's authenticated, typed, per-model choices. Catalog values include per-model efforts and service-tier ids.
- **Phase 2b / Codex speed:** `gpt-6-luna` reports `priority` named `Fast` with description `1.5x speed`; its default tier is null and separate `additional_speed_tiers` contains `fast`. `serviceTierForTurn: "default"` expresses standard. Keep the tier fields distinct and do not hard-code a universal ID.
- **Phase 2b / Codex instructions:** schema exposes `developerInstructions` and `baseInstructions` on both start and resume. It does not establish preservation or effective application; re-send/verify on resume and record only request/applied snapshots separately.
- **Phase 2b / OpenCode model and effort:** the verbose model catalog provides per-model variant keys (Director-verified host shell). Build the thinking picker from the selected model's keys and hide it where no variants exist. ACP exposes model/mode and accepts model changes through `session/set_config_option`; variant selection over ACP remains unverified. `mode` is build/plan, not effort.
- **Phase 2b / OpenCode instructions:** `OPENCODE_CONFIG_CONTENT` is honored and can set an agent prompt; it is process config. Use isolated config/env per blob process. ACP prompt text is user-turn content, not a replacement for the agent prompt.
- **Usage capture / OpenCode:** consume ACP `usage_update`. Store `used`/`size` as context-window usage/limit and `cost.amount` as cumulative session USD. The notification has no input/output/cache split, so keep those token buckets unknown rather than zero. Bloblex currently ignores the update and advertises `usage: false`.
- **Phase 2b / verification gate:** schema/request fields and debug-config resolution are not proof that a provider used a setting. Require a small adapter integration check for model/effort/tier/instructions and event fields, without treating prompt text as safe-to-log output.
