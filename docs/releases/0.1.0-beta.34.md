# Bitbots 0.1.0-beta.34

The owner's beta.33 review and a friend's test run, fixed in one wave. Claude conversations
resume after a restart, a permission can change in the middle of a conversation, and the
Manager now runs a team the way you run lanes: several conversations at once with one bot,
a panel that shows what is working, and a Manager that asks before it changes anything. If
you run beta.32 or beta.33, this version downloads by itself and shows **Restart to update**
in the top bar.

## New

- **The Manager can work across your team.** It lists and reads bots, projects, conversations
  and their status. It proposes new bots and projects, changes to a bot's name, description,
  role, instructions, look, model, effort or permission, tasks for a bot, and opening a
  conversation. Every change waits for your approval on a card. It picks the bot by role,
  tag and project, asks you with options when it is unsure, and proposes a new bot or project
  when none fits. A task it hands out says what to do, what done looks like and what to send
  back.
- **Tags.** Bots and projects take tags. You set them, or the Manager does, except on a locked bot.
- **Working bots panel.** In the side panel, the bots working on tasks: status (working,
  waiting, waiting for approval, limited, done, failed) and elapsed time. Click a row to open
  that task's conversation and watch it live.
- **Many conversations with one bot.** A bot has no cap of its own. The setting **Bots
  working at once** (Settings › General, default 4, from 1 to 16) limits the total across
  all bots. A conversation that has to wait says so.
- **A separate copy for code tasks.** When another task is already working in the same git
  project, a coding task runs in its own git worktree. When it finishes, a **Merge a task**
  card offers to merge it back: Merge, Keep branch or Discard. Nothing merges without your OK.
- **Lock a bot** (Experimental). Right-click a bot to lock it. A locked bot's settings cannot
  be changed, and the Manager never locks itself.
- **Model under the name** (Experimental). The line under a bot shows its model and effort,
  such as "Sonnet 5.5 · High", instead of the last message.
- **Settings › Experimental.** Every experimental feature now lives on its own page.
- **Steer or Queue.** Settings › General decides what happens when you send while a bot is
  working. **Steer** reaches the bot now where the provider supports it. **Queue** waits for
  the turn to end. Ctrl+Enter sends the other way. Where steering is not possible, Bitbots
  queues and says why.
- **Export diagnostics** (Settings › General, and the Help group of the Ctrl+K switcher). It writes one zip: recent
  logs, the last app events with message text removed, app and system versions, the names
  and versions of the coding agents, and your settings without secrets. You see the list
  before you save. Nothing is uploaded anywhere.
- **Readable activity.** A turn's steps are grouped as Commands, Files, Searches, Edits and
  Other, and name the file or folder they touched. The full command is there when you open
  a step.
- **Usage limits.** A conversation that hits a usage limit shows **Limited until** and the
  time, and carries on when the window opens. This is on by default; you can turn it off
  under Settings › Experimental.
- **Eight bot shapes.** Circle, Pebble, Squircle, Capsule, Triangle, Hexagon, Cloud and
  Droplet, all symmetrical, with two upright eyes. Shuffle and Surprise me change the eyes
  and the colours, never the shape. Bots saved with an older shape keep working: Round and
  Sun become Circle, Organic and Cat become Pebble, and Boxy becomes Squircle.
- **The Manager's star.** The Manager's badge is a white star on orange. It is the only star
  in the app.

## Fixed

- **Context lost after a restart.** Claude conversations could not be resumed. Bitbots waited
  for a signal that Claude only sends after you type something, gave up, and started a blank
  session. Resumes now go through. If a resume still fails, the new session starts with a
  short summary of the conversation, taken from Bitbots' own record.
- **Permissions in the middle of a conversation.** Changing a Claude conversation's permission
  no longer ends the next turn with "Requested execution settings were unsupported". The
  permission you pick in the composer applies to the bot and to every later conversation.
  A side conversation's permission can be changed where it is open, and the Manager can
  propose that change for approval.
- **"The coding agent took too long."** A turn that times out or is stopped by a restart is
  picked up again on the next start with "Continue where you left off.", and the same
  conversation keeps its history.
- **Permission denials say what was refused.** The notice names the kind of step and the file
  or command it was about.
- **Several conversations with one bot.** A conversation waiting for a free slot now says it
  is waiting, instead of showing an empty "Ready when you are" screen. A finished turn
  releases the next waiting one.
- **Sidebar previews** show the last real message, not "Started a fresh session" notices.
- **"not_found: session not found"** when you changed permission on a bot with no conversation
  open. The change now applies to the bot.
- **Allow remote devices with Tailscale** no longer fails silently. The real reason is shown,
  for example when another copy of Bitbots already serves Remote. A port inside a Windows
  reserved range no longer blocks Remote, and Remote moves to the next free port.
- **Companion** no longer snaps to the screen corners while you drag. It moves freely, and
  its position is saved once you stop.
- **Update badge** no longer covers the conversation title.
- **Usage** shows "N/A" or "No usage yet" for a day with nothing recorded, not "Unknown".

## Changed

- **Full access is the default for new bots**, in onboarding, the create wizard, the Manager
  setup and the bot templates. Existing bots keep their setting. Automations never run with
  bypass, and the Manager cannot give a bot Full access.
- **Steer or Queue** is a visible setting (see New).
- **The composer writes the bot.** Model, effort and permission choices apply to the bot at
  once, and to every later conversation.
- **Usage dialog** is shorter. "Reported by each CLI account" sits beside the heading, with an
  info icon that explains it.
- **One search box.** Click it to open the quick switcher (Ctrl+K).
- **Update banner** buttons match the app. Below about 1180 px the update badge shrinks to an
  icon and a short label.
- **Settings** groups are divided by lines.
- **Launch checklist** rows line up in a centred block.
- **The Manager card** stays in the sidebar until you have a Manager.
- **Remote in a desktop browser** opens a wide layout, with the conversation list beside the
  chat. On a phone you get the phone layout. "This device" lets you choose Auto, Phone or Wide.

## Verification

- Rust workspace, excluding the desktop crate: 877 tests passed, 0 failed. Clippy with
  `-D warnings` is clean.
- Desktop crate library: 61 tests passed.
- Desktop UI (Vitest): 1290 tests in 174 files passed.
- The main, remote and preview web builds succeed.
- No sparkle icons remain. The Manager's star is the only star.
- Real coding agents, run live outside the normal gates: Claude Haiku 5.5 and OpenCode pass,
  including the Claude permission change. Codex accepted a steer; its two-turn run was a
  reported usage-limit skip, because the account is out of quota.
- The recorded live transcripts are replayed through the real adapters in every gate, so a
  regression in those paths fails without spending tokens.
- Most of the new behaviour is tested with fake agents, a fake Tailscale command and temporary
  databases. The live checks above cover only what they name.

Unverified: pairing from a real phone over Tailscale or Native Remote (a real router and
mobile data), the native windows (the companion drag, a second launch focusing the first
window, the Working bots panel and the wide Remote layout in both looks and both themes), the
update from beta.33 to this version on a real install, the Manager's routing with a live model,
and the exact conversations the friend reported.

## Installation

Running beta.32 or beta.33: wait for **Restart to update**, or check now in Settings › Updates.
Older versions: download `Bitbots_0.1.0-beta.34_x64-setup.exe` and verify it against
`SHA256SUMS.txt`. The installer is not Authenticode-signed (Windows may warn).
