# Bloblex 0.1.0-beta.26

An OpenCode 2 follow-up for conversations. **Verified with unit tests, the
standard gates and a live three-turn run against OpenCode 2.0.28 on the machine it
was built on, using one of OpenCode's free models.**

## Fixed

- **An OpenCode conversation no longer breaks when the blob's instructions
  change.** On beta.25 a message could fail with "provider protocol error:
  instructions are fixed for the running OpenCode process", and every message
  after it failed too until a new conversation was started. OpenCode reads a
  blob's instructions only when its process starts, and Bloblex's instructions
  include the team context: the blob's role, project, your name, and whether it
  is the team leader. Making a blob the leader (which also demotes the previous
  one), or editing its role, changed the text under a running conversation.
  Bloblex now restarts OpenCode with the new instructions and reloads the same
  conversation, so the history is kept and the next message simply works.
- **Unchanged instructions never restart anything.** Only a real change does.
  Another conversation that shares the running process is not interrupted, and
  if the restart itself fails the old connection stays usable and the real error
  is shown.

## Verification

- Rust workspace excluding the desktop crate: 502 tests pass (5 new for the
  restart: changed instructions, shared process, unchanged text, environment
  change, load rejected, restart failure). `cargo clippy --workspace --exclude
  bloblex-desktop --all-targets -- -D warnings` passes. The daemon binary tests
  need `RUST_MIN_STACK=33554432` on this machine (pre-existing).
- Live against OpenCode 2.0.28 with `opencode/big-pickle`: turn 1 answered the
  first instruction, the instructions were changed, turn 2 on the same
  conversation answered the new one and succeeded, and turn 3 (unchanged) also
  succeeded.
- No desktop source changed since beta.25.

Known test flake (not new): `catalog_timeout_kills_the_child_and_failure_is_provider_unavailable`
can fail on the first run after the adapter is rebuilt on this machine (a slow
first launch of the freshly built test binary); it passes on re-run and fails the
same way on the commit before these fixes.

Unverified: a restart while the blob is also changing model or effort in the same
message, other OpenCode 2 releases, and clean-machine installation.

## Manual installation

Download `Bloblex_0.1.0-beta.26_x64-setup.exe` and verify it against
`SHA256SUMS.txt`. The installer is unsigned (Windows may warn). No updater
manifest is published; the signed `channel-beta` feed remains at beta.6. Install
beta.26 manually over your current version.
