# Bitbots 0.1.0-beta.33

Remote pairing finally completes on both Tailscale and Direct, a bot without a conversation
opens cleanly, and no more star icons. If you run beta.32, this version downloads by itself
and shows **Restart to update** in the top bar.

## Fixed

- **Remote pairing on a phone or another browser.** The computer refused the phone's "have
  I been approved yet?" check, because browsers don't send the header Bitbots required on
  that kind of request. So on Direct the phone stayed on "Approve on your computer" even
  after you approved it, and on Tailscale the page fell back to the code screen and could
  re-send a code that had already been used ("That code did not work"). Now:
  - the phone moves on as soon as you approve it, on both methods;
  - a failed check no longer sends the phone back to an earlier screen, and a reload no
    longer re-sends a used code;
  - errors say what actually went wrong (wrong code, wrong address, too many tries,
    can't reach the computer).
  Cross-site requests are still refused, and everything else about pairing (one-time code
  or password, your approval) is unchanged.
- **Turning Tailscale Remote off** now removes Bitbots' address from Tailscale again (the
  installed Tailscale no longer lists that command in its help, so Bitbots had skipped it).
- **Clicking a bot that has no conversation** selects it at once and shows a message box.
  It no longer flashes, jumps to the first bot in the list, or saves an empty conversation
  named after the bot. The conversation is created when you send the first message and is
  titled from it.
- **Branch lines** under a conversation's bot-to-bot chats are continuous in the classic
  look too.

## Changed

- No star or sparkle icons anywhere. The Manager's badge and menu entries use a briefcase,
  What's new uses a newspaper, and pinned notes use a pin.

## Verification

- Rust workspace excluding the desktop crate: 728 tests passed; clippy clean.
- Desktop crate library: 64 tests passed.
- Desktop typecheck and 1157 tests pass; the main, remote and preview web builds succeed.
- New end-to-end tests pair a device over Tailscale and over Direct with requests shaped
  exactly like a browser's (cookies kept, no header on reads), through to chatting and the
  live event stream.
- The causes were found on the owner's own install: the activity log showed both Direct
  approvals succeeding, and the live address refused the approval check without the header.

Unverified: pairing from a real phone (in particular whether iPhone Safari keeps the device
cookie), removing the live Tailscale address on turn-off, the automatic update from beta.32
to this version on a real install, and the installed native windows.

All fixes were written by DeepSeek V4.1 Flash lanes from written briefs, then reviewed and
checked before release; the icon change was made directly.

## Installation

Running beta.32: wait for **Restart to update**, or check now in Settings › Updates.
Older versions: download `Bitbots_0.1.0-beta.33_x64-setup.exe` and verify it against
`SHA256SUMS.txt`. The installer is not Authenticode-signed (Windows may warn).
