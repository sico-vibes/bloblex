# Bloblex 0.1.0-beta.24

A hotfix for OpenCode 2 and for Codex team instructions. **Verified with unit
tests, the standard gates and a live probe of the OpenCode catalog on the
machine it was built on. The Codex instruction update is sent but not verified
against a live Codex turn.**

## Fixed

- **OpenCode 2 conversations and the model catalog work again.** Bloblex started
  OpenCode as `opencode acp --cwd <folder>`. OpenCode 2 has no `--cwd` for `acp`:
  given it, the CLI prints help text and never answers the protocol, so the
  settings screen said "The provider could not be reached", the model list was
  empty, and conversations could not start. Bloblex now relies on the process
  working directory and the folder in `session/new`, which work on OpenCode 1.x
  and 2.x.
  Live on the build machine against OpenCode 2.0.28: the catalog returned 115
  models and the current model's effort levels in about 2 seconds.
- **The effort picker gets levels from OpenCode 2.** OpenCode 2 reports reasoning
  levels only for the model that is currently selected, so those levels are
  attached to that model; other models show "model default" until selected.
- **A Codex blob learns it is the team leader.** A Codex thread kept the team
  instructions it was started with. A blob made leader (or whose role, project or
  user name changed) after its conversation began kept being told it could not
  create blobs, and so refused. Changed instructions are now sent with the next
  message, and again when a conversation is resumed.

## Changed

- **Honest reporting of that update.** Bloblex records the update as applied only
  when Codex reports the new text back. With no report it says "sent,
  unverified"; if Codex reports different text, or rejects the turn, it says not
  applied and tries again on the next message. The saved thread hash moves only
  on that evidence.
- **The Codex note in blob settings** no longer says instructions apply only to
  new conversations; it now says they are sent with the next message, including
  in existing conversations.

## Verification

- Rust workspace excluding the desktop crate: 494 tests pass (11 new: the
  OpenCode 2 launch and catalog against a fake CLI that prints help on `--cwd`,
  the Codex instruction update, echo evidence, plan-mode restore, resume, and the
  storage hash rule). The daemon binary tests need
  `RUST_MIN_STACK=33554432` on this machine (pre-existing).
- Desktop: typecheck and 522 tests.
- Live probe: the fixed catalog code against OpenCode 2.0.28 (`config_options`,
  115 models, 2.3 s).

Unverified: a real OpenCode conversation end to end (only the catalog was run
live), whether the installed Codex honours the instruction update on a running or
resumed thread (it is sent, and the check is the echo), other OpenCode 2
releases, and clean-machine installation.

## Manual installation

Download `Bloblex_0.1.0-beta.24_x64-setup.exe` and verify it against
`SHA256SUMS.txt`. The installer is unsigned (Windows may warn). No updater
manifest is published; the signed `channel-beta` feed remains at beta.6. Install
beta.24 manually over your current version.
