# Installed runtime capabilities for Phase 2b

## Shared provider processes

Codex app-server and ACP keep one lazily started process per process key. Each key is a SHA-256 fingerprint of the runtime id, executable and launch arguments, project working directory, the allowlisted per-session environment overrides, provider config where applicable, and a fingerprint of the daemon's inherited environment. The inherited environment is fingerprinted in memory; its values are never logged. Different working directories or effective environment values get separate children.

ACP also keys on the exact Bloblex-owned `OPENCODE_CONFIG_CONTENT` generated for the session. That content carries the process-level model and instructions, so differing configurations cannot share a child. Codex model, effort, approval policy, and developer instructions are sent on thread start/resume or per-turn protocol requests; they are thread scoped and do not affect the app-server child, so they do not split its process key. The instruction hash rule still requires a new Codex thread when instructions change.

### OpenCode environment policy

The read-only model listing runs `opencode models --verbose` with the daemon's inherited user environment. It removes inherited `OPENCODE_CONFIG_CONTENT` so a prior Bloblex agent prompt/model cannot affect discovery. It sets or removes no `HOME`, `XDG_*`, or `OPENCODE_*_DIR` variable and does not change the working directory. The ACP config-options fallback follows the same environment policy but supplies `--cwd` and `current_dir` for a fresh empty Bloblex-owned temporary work directory, so the CLI cannot create project/session files in the daemon directory.

An ACP session inherits the user's `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`, `XDG_STATE_HOME`, and `OPENCODE_CONFIG_DIR`, `OPENCODE_DATA_DIR`, `OPENCODE_CACHE_DIR`, and `OPENCODE_STATE_DIR` unchanged. It removes any inherited `OPENCODE_CONFIG_CONTENT`, then sets that variable to Bloblex-generated JSON carrying the selected model and per-blob instruction prompt. Agent custom environment remains limited to `LANG`, `LC_ALL`, `TZ`, `NO_COLOR`, and `TERM`. No login store is opened by Bloblex; OpenCode performs its normal login lookup. The process key includes the inherited environment fingerprint and exact injected config, so changed login context or per-blob config cannot silently reuse an incompatible shared process.

Verbose model rows retain OpenCode catalog estimate rates and their original decimal spelling. The verbose metadata is sourced from models.dev, which OpenCode consumes; it is lower priority than vendor or OpenCode gateway documentation. Estimates resolve user override, the versioned official price list, cached OpenCode catalog estimate, then unknown; valuation never launches catalog discovery. A catalog zero is shown as Free only when no official row exists for that model. Rates and overrides are exact major-currency decimal strings per million tokens (up to twelve fractional digits); currency minor-unit conversion uses round-half-up once after summing all buckets. OpenCode Zen IDs use the full `opencode/<model-id>`. The Go documentation confirms `opencode-go/<model>` (for example `opencode-go/kimi-k3`); the official file stores full Go IDs, and matching also checks the catalog's parsed `providerID`.

Official tiers in `crates/bloblex-usage/data/official-prices.json` keep standard rates in the row and alternative long-context, UTC peak-window, and cache-write-duration rates in `tiers`. The turn start timestamp selects UTC time windows. When token input is unavailable, the estimator chooses the higher long-context rate and marks the result `may_be_high`; since cache-write duration is not reported, it chooses the higher published duration rate and marks the estimate the same way. Usage & limits shows the tier conditions beside each model price.

A single stdout reader per child routes JSON-RPC responses by request id and provider notifications by Codex `threadId` or ACP `sessionId`. Session routing and turn state remain separate. ACP close sends `session/close` before removing that route. The recorded Codex protocol has no client request to unload a thread: `thread/archive` changes conversation archive state, while `thread/closed` is a server notification, so closing a Bloblex session drops only its route. When the last attached session closes, `SHARED_PROCESS_IDLE_SHUTDOWN` is 30 seconds; daemon shutdown closes all adapter process trees immediately. Pause all cancels active turns without terminating a child still attached to another session. The child is reclaimed after the final route closes and the idle timeout expires; surviving conversations resume on their next prompt.

If a child exits unexpectedly, every attached session receives a provider-process error. Active turns receive failed, unreported usage and enter the daemon's existing failure and reservation-reconciliation path. The next prompt lazily starts a replacement and resumes each session (`thread/resume` or `session/load`); rejected-resume fallback starts a fresh provider session where supported and emits `SessionStarted` so the daemon persists the replacement provider id.

Each session has a FIFO forwarding queue before the daemon's bounded 256-event channel. At `SESSION_FORWARD_QUEUE_COALESCE_CAP` (128 pending items), assistant and thinking deltas and per-tool progress updates merge into the newest same-kind pending stream event, without crossing any non-stream event. If there is no safe match, the delta remains queued and may take the queue above the cap. Every non-stream event (including `ToolStarted`, `AssistantMessage`, `FileChanged`, lifecycle, permission, usage, error, and tool completion) is always retained in order and may also take the queue above the cap. A failed relay send closes that session queue and later enqueues report not-delivered. The shared reader only enqueues, so a blocked daemon channel stalls that session's relay, not other sessions. Claude Code stays one process per session because its CLI session model does not support this multiplexing. This is adapter-internal; the UI IPC contract is unchanged.
**Scope/date:** Read-only capability spike against the installed Windows npm shims on 2026-10-02. Installed versions observed: Claude Code 2.1.286, Codex CLI 0.159.3, OpenCode 1.18.34. This file merges the repo capability record with the impl-b probes that were still missing or marked too weakly, then separates behaviour from host catalogs. It is a snapshot of these CLI builds, not a promise about later releases.

## How to read this

- **CONFIRMED** means installed help, a generated schema, this repo's adapter source, or a live no-model probe directly showed the behaviour. **REFUTED** means that evidence contradicts the plan claim. **PARTIAL** means only part of the claim is established, provider-side application was not observable, or the only evidence for a behaviour is a binary string. **UNVERIFIED** means the evidence does not settle it.
- Binary-string hits inside `claude.exe` or `opencode.exe` never carry a behaviour row by themselves. Where they appear, the evidence kind is named **binary string** and the row stays PARTIAL unless a live no-model probe also showed the behaviour.
- **Behaviour** facts (flags, schemas, protocol shapes) are properties of these CLI builds. **Host-dependent** facts (model catalogs, counts, defaults, prices, credentials) are true only of the named profile on the named date. Do not generalise a count or a `default` alias from one profile to another.
- Profiles cited below:
  - **Real host, Director-verified, 2026-10-02:** the user's real profile, re-checked by the Director (not this Task 4B session).
  - **Real profile, QA-reported, 2026-10-02:** reported by QA; the Director did not re-verify the count or the default.
  - **Isolated redirected home, impl-b, 2026-10-02:** the Cursor launcher home (empty of the user's Claude/OpenCode catalogs). Counts from this profile do not describe the real machine.
  - **impl spike, 2026-10-02:** the probes already recorded in the previous revision of this file. Claude turns used default session persistence (not an isolated home). Codex warned it could not write `C:\Users\user\.codex\tmp\arg0`.
- Evidence kinds are named in each row: **help text**, **live no-model probe**, **schema**, **source**, **binary string**, or **failed-request probe** (a turn was attempted and the provider returned an error; zero usage from that event is not a successful turn).
- **Status scorecard:** CONFIRMED 12 / REFUTED 1 / PARTIAL 9 / UNVERIFIED 0 across C1–C7, X1–X8, and O1–O7.
- No credential, account identifier, provider key, or private configuration value is included. Prompt text shown is synthetic.

## Z2. Per-adapter custom-argument allowlist

User-supplied `extra_args` start **empty** on every adapter. Model, effort, tier, and instructions are typed adapter-owned fields. They must not be duplicated through `extra_args`. Paths on file flags must be files Bloblex created.

**Claude flags the adapter may add** (live-probed or help-backed on 2.1.286): `--model`, `--effort`, `--append-system-prompt-file`, `--system-prompt-snapshot`. `--fallback-model` was proposed and was **not** probed; do not send it until a help or flag probe shows it exists (**UNVERIFIED**).

**Never user-controlled for Claude:** `-p` / `--print`, `--output-format`, `--input-format`, `--verbose`, `--include-partial-messages`, `--include-hook-events`, `--permission-mode`, `--permission-prompt-tool`, `--permission-prompts`, `--resume`, `--continue`, `--session-id`, `--fork-session`, `--dangerously-skip-permissions`, `--allow-dangerously-skip-permissions`, `--settings`, `--setting-sources`, `--mcp-config`, `--strict-mcp-config`, `--plugin-dir`, `--plugin-url`, `--agents`, `--agent`, `--add-dir`, `--tools`, `--allowed-tools`, `--disallowed-tools`, `--bare`, `--safe-mode`, and `--system-prompt` (replaces the prompt and puts text in argv). Also the adapter-owned model, effort, and instruction flags above, plus cwd (`current_dir`).

**Codex:** user allowlist empty. The adapter owns `app-server`, `--listen`, `approvalPolicy`, and `sandbox`. Model, effort, tier, and instructions are JSON-RPC fields.

**Never user-controlled for Codex argv:** `--listen`, `--stdio`, `-c` / `--config`, `-s` / `--sandbox`, `-a` / `--ask-for-approval`, `--dangerously-bypass-approvals-and-sandbox`, `--dangerously-bypass-hook-trust`, `-C` / `--cd`, `--profile`, `--strict-config`, websocket and auth flags, and the thread/turn payload.

**OpenCode:** user allowlist empty. Model, effort, and mode are ACP config options. Instructions are Bloblex-owned `OPENCODE_CONFIG_CONTENT`. A later `--pure` or log-level flag is not on the allowlist until a test shows stdout stays protocol-only.

**Never user-controlled for OpenCode argv:** `acp`, `--cwd`, `--port`, `--hostname`, `--auto`, `--pure`, `-m` / `--model`, `-c` / `--continue`, `-s` / `--session`, `--prompt`, `--agent`, and the `run`, `serve`, and TUI subcommands.

Custom environment keys are a separate explicit allowlist, reject secret-looking names, and are never logged as values.
