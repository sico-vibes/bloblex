# Bloblex 0.1.0-beta.7

## Changes

- Retire budget enforcement, monetary pricing, subscription settings, and cost analytics from the active app while preserving existing local records.
- Keep token usage analytics and add a compact Codex quota meter with reset windows in the existing Usage sheet.
- Poll Codex quota through its structured app-server interface in the background; provider quota data never blocks message submission.
- Remove the unused budget, pricing, and subscription UI and model-price metadata from active provider catalog responses.
- Start a fresh Claude CLI session when execution options change before the first prompt, rather than resuming a provider session that has not received a prompt.
- Use Claude's stream-json host permission channel without configuring `stdio` as an MCP permission tool.
- Include bounded, credential-filtered provider diagnostics on failed turns and no-progress timeouts.
- Publish runtime discovery after daemon readiness so startup is not held up by CLI probes.
- Reconcile failed-turn details and asynchronous runtime discovery in the desktop client.

## Verification

- Claude adapter lifecycle and daemon timeout-diagnostic tests pass.
- A live Claude Sonnet turn completed through Bloblex's daemon using an isolated database after the local Claude CLI configuration was corrected.
- Desktop typecheck, 321 Vitest tests, and the production build pass. Focused storage, daemon, and provider-adapter suites pass with an isolated temporary directory.

## Known limits

- The quota meter currently supports Codex only; Claude and OpenCode have no verified quota source that reuses their existing CLI sign-in.
- Codex quota polling has fake-protocol coverage but no live quota fetch or native-window verification.
- The Windows installer is not Authenticode-signed.
- No clean-machine install or full native interaction acceptance pass was run.
- The live-provider smoke covered Claude only.
