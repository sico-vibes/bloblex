# Bloblex 0.1.0-beta.19

This is a large feature beta built from the improvement plan in [docs/IMPROVEMENT_PLAN.md](../IMPROVEMENT_PLAN.md). **Everything below was verified with fake providers, unit tests and browser fixtures. None of it has been exercised against a live Claude Code, Codex or OpenCode turn, a real microphone, or a clean-machine install.** Several features are off by default; the list says which.

## Changes

- **Message queue and send later:** keep typing while a blob is working. Enter queues the message and Stop is its own button. A banner above the composer lists waiting messages (edit, reorder, send next, remove) and shows when the queue is paused after a failed or stopped turn. A clock control schedules a message for later; it sends only while Bloblex is running and the computer is awake. The island composer queues typed text and stops the turn when empty.
- **Steer a Codex turn (off by default):** Settings → General → Experimental → Steer a running Codex turn. Uses Codex's `turn/steer` request; if the turn already ended the text is queued instead. Claude Code and OpenCode only queue. Not verified against a live Codex turn.
- **Automatic retry (experiment, off by default):** after a provider overload, or a rate limit whose reset time is known, Bloblex can send "Please continue." once, in the same conversation. It never resends your original message, never retries sign-in or billing errors, and you can cancel a pending retry.
- **Schedules:** profile menu → Schedules. A blob can run a prompt on a schedule (daily, weekdays, weekly, every few hours, once, or custom cron) with a live preview in the schedule's time zone. Runs are limited to "safe actions only" or "read-only"; there is no bypass option and requests the safety classifier does not approve are declined. Missed runs start once, overlapping runs are skipped, three failures pause a schedule, and a global pause switch stops new runs (Pause all agents also pauses schedules). Blobs can only propose schedules, which stay off until you approve them. Runs happen only while Bloblex is running and awake.
- **Keep awake (opt-in):** Settings → General → Power asks Windows not to sleep on its own while a blob is working or a run is about to start. It never blocks closing the lid or choosing Sleep.
- **Memory (experiment, off by default):** Settings → Memory. Blobs can save short notes and see a bounded list of them with each message; you can review, edit, approve and delete notes. Notes a blob proposes for a project or everyone stay unused until you approve them, and credential-looking text is rejected. An "About you" paragraph is shared with every blob.
- **ChatGPT dictation (opt-in):** Settings → Speech → Transcription engine. On this device stays the default. Choosing ChatGPT asks for permission and uses your Codex sign-in, read from Codex's own file only to make the request; nothing is stored or logged, and dictation falls back to the on-device model if ChatGPT fails. The endpoint is private and its behaviour has not been verified live.
- **Continue in another blob:** conversation menu → Continue in another blob. Bloblex drafts a short summary plus the latest messages in the other blob's own composer; nothing is sent until you send it.
- **Per-blob notifications:** each blob can notify about everything, only when it needs you, or never.
- **OpenCode questions:** OpenCode blobs can ask you structured questions through a new tool; unanswered questions expire after 24 hours and never read as answered.
- **Reliability:** failed turns now end through one path; a timeout no longer strands queued team messages; the inactivity timer waits while you are being asked to approve something; a "context was reset" divider appears when a conversation was compacted or silently restarted a fresh session.

## Compatibility and data

- New tables for the queue, schedules and memory are created on first start. They are additive; no existing table is altered except an optional per-blob notification-level column, and there is no ledger migration. Install over the existing version to keep your blobs and conversations.
- New settings are all off by default except nothing that changes existing behaviour: queueing replaces the previous "send disabled while working" state, and the composer stays disabled while an approval is pending.

## Verification

- Rust workspace excluding the desktop crate: 459 tests passed, 0 failed. Desktop crate library tests: 33 passed (from a plain-path checkout). Desktop: typecheck clean, 497 tests passed.
- Adapter replay tests use fixtures synthesised from the in-repo fake providers, not real CLI captures.
- Browser fixtures covered the queue banner, send-later popover, Schedules page and editor, Memory page and Speech settings.
- Backend work was delegated and independently re-gated by the Director before each commit; the review notes and the fixes found are in `SESSION_HANDOFF.md`.

Unverified: live Claude/Codex/OpenCode turns through the new features, `turn/steer`, the ChatGPT transcription endpoint (WAV acceptance, Cloudflare behaviour), real retry timing, an end-to-end scheduled run, the keep-awake effect under `powercfg /requests`, a memory catalog reaching a real prompt, and clean-machine installation.

## Manual installation

Download `Bloblex_0.1.0-beta.19_x64-setup.exe` and verify it against `SHA256SUMS.txt`. The installer is unsigned (Windows may warn). No Tauri updater signature or manifest is published; the rolling signed `channel-beta` feed remains at beta.6. Install beta.19 manually over your current version.
