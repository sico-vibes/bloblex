## 2026-10-28 · Daemon and UI · Wave 13 (loop guards, schedule rules, limit handoff, bot templates, phone assignments, outside sessions)

- **The hop limit counts round trips, not nesting.** `team::after_turn` relays a reply with the side conversation's depth and the Manager's next `message_blob` adds one, so `MAX_DEPTH` (6) bounds how many sequential hand-offs one request can make. Lowering it cuts ordinary multi-step plans short; real loops are stopped by `waiting_upstream` (refuses a target already up the `originSessionId` chain) and `repeated_failure` (two identical recent failures) in `team.rs`.
- **"Did the run change anything?" is answered conservatively.** `Storage::session_acted_since` counts any file change and any tool whose kind is not on the read-only list (kinds differ per provider: Codex `commandExecution`, Claude `Read`/`Grep`, ACP `edit`/`execute`), so an unknown tool means "changed" and the run is not retried on its own.
- **Automation starts are claimed in memory** (`Automations::claim_start`, released on drop). The `automation_runs` single-flight index alone let "Run now" and the scheduler both open a conversation before one insert failed.
- **A backup coding agent is a handoff, not a model switch.** A conversation's runtime is fixed, so "Continue in another bot…" on a usage-limit notice reuses `session.handoff.draft` and the `HandoffDialog`, listing bots on another provider first; nothing is sent automatically.
- **Mounted tests: the Automations list is sorted by name**, so select a card by `.schedule-name`, not by position.
- **Test normalizers from the daemon's raw DTO, not from a hand-built record.** Wave 12 added `silent`/`doneGoal` to the delegation DTO and to `DelegationRecord`, but `normalizeDelegation` (`ui/delegations.ts`) dropped them, so "Done, nothing to report" never showed; the label test built the record by hand and passed. Fixed in Wave 13 with a test that feeds the wire shape (`workspace: {path, worktree}`).
- **A field that carries a host path must be handled in both remote redaction ports** (`remote/policy.rs` `field_policy` and `remote/remoteTiers.ts` `fieldPolicy`) and get a case in `remote/fixtures/policy-goldens.json`, which both languages run. `worktree` is dropped and `workspace.path` reduced since Wave 13; opening a method to phones also means updating the reviewed event list in `remoteTiers.parity.test.ts`.
- **Writing another program's settings:** `outside.rs` reads Claude Code's `settings.json`, refuses anything that is not a JSON object, backs it up beside itself, writes through a temp file and rename, and removes only entries whose command holds `bitbots-hook` and `--outside`. `serde_json` (no `preserve_order`) rewrites the keys in sorted order; the consent dialog shows the exact new file.
- **UI details:** `SettingsRow`'s `detail` renders inside a `<small>`, so status paragraphs go after the row (`.settings-row-note`); `ProviderLogo` is a `span`, so style a pill's label by class, never `.pill span`; a long unbroken line in a `<pre>` widens a grid dialog unless the dialog has `grid-template-columns: minmax(0, 1fr)`.
- **The installed daemon runs from a private copy** (`%LOCALAPPDATA%\com.bitbots.desktopuntime-processesitbotsd-<pid>-<uuid>.exe`), so anything that looks "beside the daemon" finds nothing in a real install. The Health check's hook row and outside watching both did; a live test that ran `target\debugitbotsd.exe` directly hid it. The shell now passes `BITBOTS_HOOK_BRIDGE` (the bridge beside the installed daemon) and `outside::hook_bridge_path` reads it first. Test install-shaped behaviour through the shell or the dev app, not a hand-started daemon.
- **Unread dots must follow new content, not `updatedAt`.** Warming a conversation (and evicting the oldest warm one) changes its state and bumps `updated_at`, so switching quickly left white dots on conversations with nothing new. `sessionSeen.attentionAt` uses the newest reply, notice or teammate message, and keeps `updatedAt` only for states that need the owner (approval, error, limit).
- **The daemon supervisor only worked in a live crash test after two fixes** (2026-10-28, found by force-ending the dev app's daemon five times). The window's `ensure_daemon` started the daemon whenever it reconnected, so it raced the backoff and overrode "gave up"; and the backoff counter reset on every successful restart, so the wait never grew. Now `ensure_daemon` refuses while the supervisor is `restarting` or `gave_up` (`supervisor_blocks_start`), and the wait is indexed by the crashes inside the two-minute window. To repeat the test: run the dev app from a short path and end the `bitbotsd-<pid>-<uuid>.exe` under `%LOCALAPPDATA%\com.bitbots.desktop.dev
untime-processes`.
- **The silence watchdog already existed** (`forward_events_with_timeouts` in `main.rs`: 45 s to first output, 5 min between outputs, paused while `waiting_permission`). Wave 13 only widened it while a tool is still running (`RUNNING_TOOL_FACTOR`, 6x, so a long build or install is not stopped) and made the stop say which agent and how long (`silence_message`). Check for an existing mechanism before building one from the plan.
- **Lazy snapshot:** `app.snapshot { lazy: true }` (the window only) sends the 15 newest conversations and any busy one in full, the rest as `partial: true` with their last three messages (`Storage::snapshot_with`, `session_detail_parts`). The window's background loader (`hydrationOrder`) loads partial ones, open ones first; `mergeHydratedSession` clears `partial`. The phone keeps the full snapshot.
- **Retiring a look leaves `:root[data-bitbots="on"]` rules everywhere.** A scripted cleanup must parse selector lists, keep live selectors, drop a comment only when it belongs to a removed rule, and be checked for balanced `/* */` and braces afterwards: a comment containing a comma once came out unterminated and would have hidden the rest of `polish.css`.
- **Bash heredocs lose doubled backslashes** in this tool even with a quoted `'EOF'`, so Windows paths and escaped newlines in generated code came out wrong twice. Write such scripts with the Write tool (or build the backslash with `chr(92)`) and typecheck right after.

## 2026-10-28 · Daemon · Wave 12 (approval rules, durable team queue, cascaded stops, quiet replies, supervisor, Doctor)

- **The ledger finishes the assignment before `team.rs` relays.** `delegations::after_turn` calls `finish(..., "completed")` and only then returns `TurnEnd::Owed(row)`, so a second pass in `team::after_turn` can no longer change the row (a `(pass)` check there found it already `completed` and relayed anyway). A silent outcome has to be a ledger decision: `TurnEnd::Silent` is returned instead of `Owed`, and `delegation_mark_silent_complete` writes status and `silent=1` in one statement. **Avoid:** any new "the reply is different" rule belongs where the row is finished, not where the reply is composed.
- **Async recursion across modules needs one `Box::pin`.** `cancel_session_turn_matched` → `delegations::cancel_turn_group` → `cancel_row` → `cancel_session_turn_if_quiet` → `cancel_session_turn_matched` is an async cycle (E0733) even though the quiet path never recurses at run time. Boxing the `cancel_turn_group` future at the call site fixes the type. The cascade itself is one loop over a worklist of `(session, turn)` pairs, so the count it returns is the whole chain.
- **Every queue pop must delete its durable row.** The team queue (`team_queue`) is the truth and `st.team.queued` is a cache carrying each row's id; the drain removes the row right after `pop_front`, and the cancel helpers (`retain_queued`) remove theirs too. A pop that forgets it makes a restart re-deliver a brief that already went out.
- **`resolve_permission_policy` allowlist.** It accepts `policy:auto`, `policy:bypass`, `policy:automation` and now `policy:rule:*`; a new policy reason that is not added there makes `finish_permission_policy_reply` return `InvalidAgent`, which leaves the card `resolving` — it looks like the auto-answer silently failed.
- **`session.model.update` refuses while a turn is active** ("model cannot change while a turn is active"). A test that needs plan mode on a live turn must write the lock directly with `Storage::session_apply_model_change`.
- **File encodings differ per file.** `crates/bloblex-storage/src/lib.rs` is valid UTF-8 with one NUL and LF: a `readFileSync(utf8)`/`writeFileSync` round trip is byte-identical (verify with `Buffer.from(s,'utf8').equals(b)`), and the Read tool refuses a window that covers the NUL, so read it with `node`/`grep -a`. `crates/bloblex-daemon/src/main.rs` and `src-tauri/src/lib.rs` are CRLF: a multi-line scripted replacement must split CRLF to LF first, edit, and convert back, or it matches nothing. Shell `node -e` strips backslashes; write the script to a file.
- **Storage tests:** a new additive `ensure_*_schema` needs its own `#[test]` (the attribute is not inherited by an inserted function), and a fixture agent needs `upsert_runtime` first or `agent_create` fails `AgentNotFound`.
- **The Doctor's fixes are RPCs.** `doctor.run` only offers `runtime.refresh` and `runtime.auth.clear`, and every row's `detail` is one plain sentence; the test asserts the shape and that no detail carries a secret word. Free disk space was skipped: no crate in the workspace can read it without a new dependency.

## 2026-10-27 · Tooling · A "binary-safe" edit of storage `lib.rs` corrupted every non-ASCII character

- **Symptom:** after a scripted edit, `message_reaction_rpc_persists…` failed with "Reaction or message role is unsupported" and `tool_details_are_bounded…` overran its limit. Every emoji and `…` in `crates/bloblex-storage/src/lib.rs` had become mojibake.
- **Cause:** the Node helper read the file as `latin1` (to keep the NUL bytes) but wrote it with `fs.writeFileSync(file, text)`, which encodes as UTF-8. Each byte above 127 became two bytes.
- **Fix:** read the damaged file as UTF-8 and write it back with `Buffer.from(text, 'latin1')`. That only works when no character is above U+00FF and none is U+FFFD; check that first, then compare the diff and the NUL count (`tr -cd '\000' | wc -c`) with `HEAD`.
- **Avoid:** read and write the same encoding. Byte edits on this file need `latin1` on both sides (or `grep -a` plus `sed -i` on ASCII lines), and a diff check right after.

## 2026-10-27 · Round 2: durable wake, checked cancel, ambiguous sends, exhausted limits, pause (T7, uncommitted, in `main`; no tests were run)

## 2026-10-25 · Storage · `sqlite: no such table: tasks` on an existing database (FIX43, beta.37)
- **Symptom:** the installed beta.37 showed `sqlite: no such table: tasks` on the Tasks page; a fresh database worked.
- **Root cause:** `Storage::migrate` returns early in a branch per schema version (`ledger==12`, `==11`, `==10`, ...), and each branch calls its own list of `ensure_*_schema`. `ensure_tasks_schema` was added only to the last, fresh-database path (`crates/bloblex-storage/src/lib.rs`), so every database an earlier version had created never got the task tables. ## 2026-10-26 (T3 wave)

- **A second dev app must not share the identifier.** `tauri-plugin-single-instance` is keyed by the bundle identifier, so `scripts/dev-windows.ps1`'s `com.bitbots.desktop.dev` can fold into an already running review build. The T3 preview uses `com.bitbots.desktop.t3dev` and Vite ports 1440 to 1459, with its own `BLOBLEX_DB_PATH`.
- **Media and CSP.** `img-src` already allowed `data:`/`blob:`; audio and video needed `media-src 'self' blob:`. `fetch(dataUrl)` is blocked (`connect-src` has no `data:`), so decode base64 yourself into a Blob. WebView2's PDF viewer does not run in our CSP or inside a sandboxed iframe, so PDFs are a card, not an inline view.
- **A delegation turn can end before its row is "running".** `team::after_turn` runs in its own task, so a fast turn can finish before `delegations::started`; `started` must read the turn's stored state back and finish the row itself.
- **Rich tables must keep the author's text.** Converting "12%" or "$1,200" to a number for display drops the unit; keep the cell text and read the number only to sort or plot.
- **Heredocs and regex backslashes.** Writing a Node patch script through an unquoted shell heredoc strips backslashes in regexes (`\s` becomes `s`); write the script with the file tool, then run it.
- **node_modules is shared through the worktree junctions.** Adding a package: run `npm install <pkg> --workspace @bloblex/desktop --package-lock-only` in one worktree, then put the package into the main `node_modules` (or run `npm install` in main); the lanes' junctions see it at once.
- **Two spawn sites can close a future-type cycle (E0391).** A request hook in `forward_events` that awaited `deliver` made `session_prompt_impl` depend on itself; a synchronous `spawn_update` (a plain `fn` that spawns) breaks the cycle. Spawning an `async` block that awaits the delivery path does not.
- **Do not type-check tests when the owner says no tests.** `apps/desktop/tsconfig.json` includes the test files, so `tsc -p apps/desktop`, `tsc -b` and `npm run build` all compile them. For a no-tests wave use a temporary tsconfig that extends it and excludes `*.test.ts(x)` (`apps/desktop/tsconfig.prod.tmp.json`, untracked), and `npx vite build` for the bundle.
- **A PDF viewer needs three things in a Tauri CSP.** The worker must be your own bundled file (`...worker.min.mjs?url`), the viewer must draw to a canvas (no iframe), and `isEvalSupported` must be false. WebView2's built-in PDF viewer is not available in our setup.
- **A question holds its assignment open.** A side conversation's turn that ends with a pending `ask_user` card is not a result: `delegations::after_turn` returns `TurnEnd::Waiting` (no finish, no reply claim, no relay) and the answer's turn is adopted by the same running row. Anything that finishes a side assignment (cancel, fail, interrupt, restart) must also close that session's pending cards without prompting the child. The side-conversation gate in `session_prompt_impl` has to allow `PromptOrigin::QuestionAnswer`, or the answer is refused `read_only` and pauses the queue.
