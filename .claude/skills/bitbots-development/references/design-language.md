# Design language

Last reviewed: 2026-10-27 (Haze is frosted glass: native Windows backdrop blur with a tint over it; fallback 80% opaque; rich blocks, media previews, terminal dock, Needs you, workspace and checkpoint cards added). Source of truth for rules: `docs/design/design-system.md` and `docs/library/content/reference/theme-system.md`. When the owner changes a visual rule, edit the rule here in place and in `docs/design/design-system.md`.

## Product feel

A calm chat app for developers moving between coding-agent sessions. The bots supply warmth; the chrome stays quiet. Say each thing once per screen (a bot's name, state and model appear in one place). Status colour only when something is happening. In Blobots chrome that means amber for working or approval, red for failure and green only for added lines (`docs/design/design-system.md`); Frost and the bot arts' status badges follow their own palettes. One animated bot per place.

## The three looks

`appearance.style` → `<html data-style>`. Settings and onboarding use one orb row, ordered **Haze, Stone** (owner, 24 October 2026: Haze is the primary look and the default for a new install; Blobots is shown as **Stone**, stored id `blobots`). **Frost (`bitbots`) was retired on 27 October 2026** with its wallpaper and glass settings; a saved Frost moves to Haze. The orbs are one family: a dark shaded sphere crossed by one horizontal ribbon (Haze a warm wave band, Stone a soft grey band). Names appear on hover/focus, with no card subtext or visible family grouping.

## Haze: frosted glass (owner directive, 27 October 2026; supersedes "backdrop opacity" below where they differ)

Haze is **frosted glass**: the real desktop behind the main window is actually blurred, not merely shown through a transparent window. Transparency alone is not frost, and CSS `backdrop-filter` cannot do it, because WebView2 composes only its own page and never sees the desktop. The blur is drawn by Windows (DWM) and the page sits on top of it as a translucent tint.

- **Native (`src-tauri/src/backdrop.rs`, commands `window_backdrop_apply` and `window_backdrop_state`):** through the `window-vibrancy` crate, called directly because Tauri's `set_effects` swallows errors. Windows 11 build 22523+: `DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_TRANSIENTWINDOW` (the system desktop acrylic; its tint colour is ignored). Windows 10 1809+ and older Windows 11: `SetWindowCompositionAttribute` acrylic with a neutral tint, then plain blur, then nothing. The main window's `transparent: true` stays (it is what lets the compositor's backdrop through). The window theme (`set_theme`) is forced to dark or light to match the app so the system acrylic tints the same way; switching away from Haze clears the effect and gives the title bar back to the OS.
- **Scope:** the main window only, and only while the look is Haze. The command refuses any other window label, and `ui/windowBackdrop.ts` does nothing in the companion and dictation windows. Frost and Stone never get an effect and keep their opaque looks.
- **The UI follows the real result.** `ui/windowBackdrop.ts` watches `<html data-style>` and `data-theme` (so first load, the settings page, daemon hydration and the system theme all work), calls the shell and sets `data-backdrop="acrylic|blur"` only when Windows actually draws the blur and transparency effects are on. First paint: the shell stores the last request in `backdrop.json` and re-applies it during setup, and `index.html` reads the cached result (`bitbots.backdrop`) so the very first frame already has the tint. Windows' "Transparency effects" switch is read from the registry and checked again on window focus.
- **CSS (`themes/haze.css`, `[data-backdrop] .haze-backdrop`):** with `data-backdrop` set, `.haze-backdrop` is **not an opaque layer**: a thin neutral veil (34% of `--haze-base`) plus the same large blended blobs at `opacity: .85` sit over the native blur, so the blurred desktop stays visible. Without `data-backdrop` (browser preview, older Windows, effect refused, transparency off) the opaque 80% composition below applies unchanged, the fallback.
- **Density:** the old "about 80%" is the rough goal for the overall density (system acrylic plus the tint), not a number to paint over the blur. The veil and blob strengths are a starting point and were **not measured or seen** (owner rule: no screenshots); tune by eye in a development window. Never hide the blur with an opaque layer or a fake screenshot; text, controls, menus, dialogs, the settings sheet, the composer and the terminal dock keep their own surfaces and stay readable.
- **Unverified:** that Windows really draws the blur in the decorated, transparent WebView2 window, and how it looks, has not been checked at runtime. Known Windows caveat: the Windows 10 and early Windows 11 acrylic path can lag while dragging or resizing a window.

## Haze: no flat grey blocks (owner, 28 October 2026)

- Sheets, dialogs, the bot save bar, the first-run prompt and the terminal dock are frosted glass in Haze: `--haze-glass` (dark 62%, light 64%) with `backdrop-filter: blur(28px) saturate(1.15)` (`themes/haze.css`). Never put `--surface-panel` (a 97% grey) behind a Haze surface.
- **Hover is a text highlight, not a box:** in lists and rows, hover brightens or underlines the text; where a background is unavoidable, give it padding and space from the dividers around it.
- **Composer:** the provider logo in the model pill is 16 px (it must read as large as the speed icon beside it); the thinking level wears one static Brain icon (the menu keeps each level's bars); Steer / Queue sits in the composer bar beside the stop and send buttons, not in the status line above the text box.
- **Conversations panel:** the title alone in its header; one dashed full-width "New conversation" button under it; hiding and showing the panel is one toggle beside the bot's name in the main header.
- **Tables:** headers never break a word; an opened row is a two-column sheet (labels in one column, full values beside them).
- **Changes card:** at most 8 files, then "Show all N files"; a folder that is not a Git repository (always the Manager's) is explained calmly, never shown as an error.

## Haze: backdrop opacity (owner directive, 26 October 2026, corrected the same day; the fallback look when no native blur is drawn)

The main Haze window's background is **about 80% opaque, 20% transparent**, with the large blended coloured blobs kept in dark and light. (Earlier readings, "90% transparent" and "80% transparent", were wrong; the owner meant 80% opaque, and the picture had become nearly invisible.) This is the background only; text, controls, menus, dialogs, the settings sheet, the composer and the terminal dock keep their own surfaces and stay readable.

- **Native:** the main window stays `transparent: true` in `src-tauri/tauri.conf.json` (tao applies the same empty DWM blur region the companion and dictation windows use; the title bar stays native and opaque). It is what lets the remaining 20% of the desktop show through. Transparency is a creation-time window property, so changing it needs a rebuild and a restart.
- **CSS (`ui/themes/haze.css`, `.haze-backdrop`):** the non-interactive `.haze-backdrop` element paints an opaque composition (a neutral base `--haze-base`, `#1a1b1d` dark and `#f1efeb` light, under four broad overlapping radial blobs of 80 to 125 vw/vh radius with a four-stop falloff) and carries `opacity: .8` itself, so the whole backdrop composes to about 0.8. The opacity sits on this one element only: never put an opacity on a container that holds content, and do not stack another full-window tint over the backdrop. `html`, `body`, `.app-shell` and the panes stay transparent; the sidebar tint is 8%.
- **Stone stays opaque.** Stone's `--surface-app` is opaque. Companion and dictation windows are unchanged (opaque smoke).
- **Legibility:** text now sits mostly over the opaque base, so contrast depends little on the desktop behind. Nothing was measured in this pass (owner rule: no screenshots).

## Haze: the status gradient (owner directive, 24 October 2026)

In Haze the status of a bot is a soft gradient rolling in from the right of its row (`blob/haze/HazeAura.tsx`), the owner's exception to "no decorative gradients". It shows only while the bot is doing something or is selected; the Manager keeps a still golden fade. Speed and colourfulness carry the state: selected-idle slow and muted, thinking two close hues, working fast with three hues, needs-you breathes amber, a failure falters in red, done sweeps green once. A change of state cross-fades (900 ms), never cuts. The same gradient marks the conversation header, the companion bar, focus card and teammate rows. Put it behind content with `z-index: -1` inside an `isolation: isolate` parent; never make the parent's children `position: relative` to lift them (see lessons, 2026-10-24). Tinted logos are inline SVG with their inner marks cut out (Codex's prompt glyph, OpenCode's inner block at 38%), not a CSS mask of the whole file.

Haze character portraits keep their source SVG colours. The bot colour belongs to the status aura, not the character artwork. Small marks and picker cells load the static SVG; larger avatars load the animated SVG by URL so SVG-internal animation stays scoped. Saved `char-*` values are ignored by Frost and Stone renderers and preserved when switching looks.

## Rules that apply to every look

- **Shape:** rounded rectangles like the logo (`--radius-sm 9px`, `--radius-md 12px`, `--radius-lg 16px`, `--radius-pill 12px`, panels about 20 to 22 px). No pill or circle controls or surfaces: buttons, chips, composer, toggles and knobs, segmented controls, swatches and avatar frames are rounded rectangles. Exceptions: the circular Manager badge and locked-bot badge on avatars (`docs/design/design-system.md`), and the look orbs (the owner asked for orbs). Bot artwork is not UI and keeps its own shape.
- **Flat:** no glow, no halo, no decorative gradients, no text shimmer (the owner's words for Frost: "slick, smooth, premium; no glow"). Shadows only where a look's own language has them, or one soft shadow on floating menus and dialogs.
- **Readable selection:** in any look that fills a selected row, every descendant of the selected element takes the selected text colour (names, role chips, times, status lines, icons). Dot (inverted) and Pop (butter) were the two that needed it, and both were removed on 20 October 2026. This was missed twice (FIX40, Dot and Pop); test any filled selected row in dark and light.
- **Contrast:** body text at least 4.5:1 against the surface it sits on, including over wallpapers at the default glass level.
- **Keep focus rings and selected states visible.** Never blanket-remove `box-shadow` (the focus ring is a box shadow).
- **User accent wins:** `--user-accent` (from `appearance.accent`) overrides each look's default accent.
- **Scope everything** to the look: `:root[data-style="<look>"]:not(.companion-surface):not(.dictation-surface)` for the main window, and separate `.companion-surface` / `.dictation-surface` sections for those windows.

## Companion, conversation tree and message buttons (FIX43, 25 October 2026)

- **One companion layout for every look.** Expanded, the companion is the split layout in `Companion` (`ui/App.tsx`, `.companion-shell` in `ui/companion.css`): the bot list on the left, the open bot's header and one pane on the right (chat, approval, activity, settings, drop target, side conversation), approvals and everything else in that pane, the compact bar unchanged. Frost and Stone keep their own bot art and status marks in the list (mascots at 24 px, with the art's own status badge); only Haze adds its gradient (`themes/haze.css`, the rules for `.cs-bot > .haze-aura` and `.cs-head > .haze-aura`). The old island (overview cards, tab header, teammates grid) is gone. Shared layout rules read the companion surface tokens (`--surface-sidebar`, `--surface-selected`, `--line`, `--text-*`), which every look defines.
- **Resizable, always on top.** The window is frameless and transparent, so eight handles (`CompanionResize.tsx`, `.cs-resize-*`) drive the shell's `companion_resize_*` commands from the real cursor position. Minimum 520 x 340, maximum the work area, the size is remembered (`companion-size.json`), the header's "Make larger" toggles a 960 x 720 size, Settings has "Reset size". The compact bar is fixed at 344 x 62. The old Compact/Comfortable/Tall height setting is retired (the daemon still accepts the `companion.chatSize` key; nothing reads it).
- **Branch tree.** In the Conversations column the trunk starts below the parent card (a 3 px gap, nothing drawn inside the parent row) and runs down to an elbow into each child, as in Claude Code's branch tree.
- **Message buttons** (time, copy, reply, react) are centred on the bubble: the row inside `.message-action-shell` has no margin of its own.

## Composer and sent images (FIX44, 25 October 2026)

- **The composer card owns its status, and shows it only when there is some.** The queue count, the steer/queue choice, "Paused", an automatic retry and the reason a message queued live in one 22 px row inside `.composer-box` (`ComposerStatus` in `ui/PromptQueue.tsx`). When there is nothing to say (no queue, no busy turn, no pause, retry or notice) the component renders nothing, so an idle composer has no blank strip above the input (27 October 2026 correction; the row used to be reserved "so nothing moves", which the owner saw as empty space). Queue rows unfold from their count chip on request; do not render a banner above the card again.
- **One attachment control.** A single paperclip (`AttachMenu` in `ui/ComposerControls.tsx`) opens a menu with *Image* (bytes, only for agents that accept images, up to the per-message limit; same validation, drag and paste as before) and *File by path* (document, audio or video; sent as a path only, Bitbots never reads it). Each choice disables itself with its reason shown; the paperclip is disabled only when both are. Never put two attachment buttons in the control strip again.
- **Sent images stay pictures.** A message's image is a 132 px thumbnail from the message's own record (`message.image`), with a viewer on click (Escape and the backdrop close, focus returns to the thumbnail) and a dashed "Not available" placeholder when the file is gone. Never an arbitrary path read, never a broken `<img>`.
- **Hit targets and popovers size themselves.** A remove control is a 24 px square with the glyph centred and the usual focus ring. A picker popover is as wide as its content, capped to the window (`width: max-content`), and its labels wrap rather than ellipsize.

## Rail, drafts, delete and dictation (FIX45, 25 October 2026)

- **Dictation is the recorder bubble only.** No live words, no "Words appear when you stop" line, no cloud note in the island, bubble, companion or composer banner. The final transcript goes into the box when recording stops; a failure shows one plain error line.
- **The rail's Changes card is the repository's state.** It lists Git's working tree against HEAD with the real branch and +/− totals, and says so in its heading. Files the conversation recorded stay under "Edited earlier in this conversation". Never imply that the conversation wrote every change.
- **Create PR always asks first.** The dialog says it sends the whole repository's uncommitted state, and the dialog closes only after the daemon accepts the message.
- **Hold to delete keeps one footprint.** Idle, holding, armed and pending read the same size and place; the armed label is short (`Release to <first word>`), and the button never scales.
- **Archived bots** show three skeleton rows with a status label while they load.
- **Drafts stay in the box.** A typed draft is never cut short on screen; only the restart backup is bounded.

## Composer, model switching and conversations (T7, 27 October 2026)

- **Steer or queue is a choice, not a hidden key.** While a turn runs, the composer's status row shows two small choices, *Steer now* and *After this turn* (`ComposerStatus`), the placeholder and the send button's glyph follow it (arrow = reaches the turn now, list-plus = queued), and *Stop and send instead* stays beside them. Steer is disabled with its reason when the coding agent cannot take a message into a live turn. The choice lasts for that turn. Ctrl+Enter still sends the other way.
- **The box stays usable while an approval waits.** Typing is allowed (the message queues); the placeholder says to answer the request above. A runtime that is not ready says so in the placeholder.
- **The model pill tells the truth.** Its description names the model and effort that apply from the next message. While a turn runs it stays focusable and says when the model can change (`.model-pill.waiting`). The menu says the choice is for this conversation and that new ones with the bot start on it. A change that keeps the provider session applies with no dialog; only a fresh session asks, in the daemon's own words, and says what stays (messages, drafts, attachments, project). A missing catalog shows a retry button.
- **Conversations are easy to find.** The column header has a labelled *New chat* button; above 7 conversations a filter field appears; a row that needs the owner reads *Needs you* (amber text) and a failed one *Failed*, in place of the time.
- **Unconfirmed delivery is said plainly.** A pending message the daemon could not confirm reads "Bitbots could not confirm the bot received this ..." with **Send again** (never a silent retry); a failed turn with unconfirmed delivery adds that it will not be sent again on its own. Copy about a model change says what is asked of the provider, never that it will succeed.
- **A queued send that may have been delivered** reads *May already have been sent* and asks *Send it again?* in the row before it resends.

## Tokens

All colours, sizes and radii come from `apps/desktop/src/ui/theme.css` tokens (`--surface-*`, `--text-1..3`, `--line*`, `--status-*`, `--radius-*`, `--shadow-pop`, `--focus-ring`, `--font-ui`, `--font-mono`, `--fs-*`, companion tokens). A look overrides tokens first and adds component rules only where tokens are not enough. Component stylesheets use tokens, not literals.

## Bot art

Per bot, offer Automatic, 3D robot (`robot`), Glossy (`blob`) and Hand-painted (`painted`) (owner, 27 October 2026). The 3D robot uses the four `look.bot.shape` outlines and shell/trim/screen controls. The 2D robot (`robot-pop`) and the flat and dot robots it stood in for are retired and their renderers deleted: saved ids still pass the daemon's `valid_look` (`RETIRED_ARTS`), are stored as `robot` (`normalize_retired_look`, storage startup) and resolve to the 3D robot in the app (`RETIRED_ROBOT_ARTS`, `resolveArt`, `normalizeLook`). Automatic is Glossy in both looks. Hand-painted has twelve `look.paint` shapes; its body stays still, its eyes blink and large avatars track the pointer (`useEyeTracking.ts`). Mini avatars have no pointer listener; listeners and animation frames are cleaned up, and reduced motion stays still. Corner status badges retain their meaning. Manager badge: white star on orange.

The update notice lives immediately above the profile in the left sidebar, including without a selected conversation. Settings use row-shaped skeletons while loading. Finished tasks use two lines, with status/time beside the name. Selected and hovered surfaces must pair every descendant with readable text; user-bubble links inherit the bubble foreground.

## Copy

Plain, short, sentence case, British-neutral, no exclamation marks, no marketing words. The entity is a "bot" in every look. Say what happens, not how clever it is.

### Haze portrait sizing (26 October 2026)

Static SVG viewports centre the complete head with 3% clearance per side. Picker buttons explicitly reset inherited art-button padding/gap and use definite minmax(0,1fr) tracks; contain/centre the full image without clipping. Picker cells are 52px tall with 4px padding. Character marks have a 26px minimum in the shared renderer; sidebar rows remain 36px. Animated art retains movement clearance.

The OUTER `.blob-page-layout` is capped at 880px, moderately wider than the original 640px rather than filling the screen. Its inner column fills that layout. The Look preview column is 320px so all five status buttons fit in one nonwrapping line; the choices occupy the remaining width. Keep stronger Haze-specific button selectors to prevent inherited padding from clipping portraits.

Hide the Colour control when a premade `char-*` portrait is selected. Show it again for runtime logos and pixel art. Keep the saved bot colour when switching; do not recolour the portrait or reset the existing aura colour.

## Manager assignments (FIX47, 26 October 2026)

- **One "Messaged" chip per Manager turn** (owner, 28 October 2026; it replaced the FIX47 card): centred like "Message from", reading "Messaged [up to three bot arts] Vex, Coco +2 · 4 done · 58s" with a caret; clicking opens the rows in place below it, centred, between two hairlines, with no card box. Each row: chevron, the bot's art, name and topic, then the status in its own column on the same line as **Open**, then Stop. The details panel sits under the row with room above and below.
- **Honest labels:** Queued, Working, Needs approval, Done, Failed, Cancelled, Interrupted, and "Earlier message" for pre-ledger messages. Approving stays in the teammate's conversation; the card only navigates. A shared folder's branch and changes read as the folder's ("whole folder, not only this bot"); only a worktree's own branch is attributed to the bot.

## Rich blocks, media, terminal and review cards (T3 wave, 26 October 2026)

- **Rich blocks in chat** (`ui/RichTable.tsx`, `ui/RichChart.tsx`, `ui/richData.ts`, `ui/richBlocks.css`): every Markdown table is an interactive table (sort by column, filter from 9 rows, open a row to read every cell, copy CSV, 12 rows then "Show all"); a table with numeric columns also offers a chart of the same cells (one numeric column plotted by default; the note says all picked columns share one axis, never a second axis). Fenced `bitbots-table` and `bitbots-chart` JSON blocks, `csv`/`tsv` blocks and `json` lists of objects get the same views; a block that fails validation stays visible as code with the reason. Cells keep the author's text ("12%"); numbers are read from it only to sort and plot. Charts: bars at most 24 px, 4 px rounded data end, 2 px lines, hairline grid, series colours only on marks (text uses text tokens), legend from two series, tooltip on hover or focus for every series, a "Data" table view, a text summary as the SVG title. The categorical series colours are the validated dataviz set in `.rich-block`. Nothing from a model is executed or fetched: no HTML, script, iframe or remote image.
- **Media in chat** (`ui/MediaPreview.tsx`, `ui/mediaPreview.css`): a Markdown image on its own line, or "Preview file" on a reported file change, asks the daemon (`media.preview`) for a file inside the conversation's project folder. Images open in the existing viewer; audio and video play from a Blob URL; text shows 18 lines with "Show all"; PDFs are a card with "Show in folder" (WebView2's PDF viewer does not run in our CSP). Loading, blocked, unsupported and too-large are labelled cards. A web image is never loaded (a link instead). The CSP gained `media-src 'self' blob:`.
- **Terminal dock** (`ui/TerminalDock.tsx`, `ui/terminal.css`, xterm.js): a bottom dock under the conversation, toggled by the header button or Ctrl+backtick, one tab per shell (PowerShell, PowerShell 7, Command Prompt), starting in the selected conversation's project (or its own worktree) folder. Transparent xterm canvas over `--surface-panel`, theme from the look's tokens, `minimumContrastRatio` 4.5, reduced motion stops the blink. Hiding the dock keeps shells running; closing a tab ends it. An exited shell shows a Restart bar.
- **Needs you** (`ui/NeedsYou.tsx`): a list above the bots with every waiting approval, question and proposal, oldest first. A row only navigates; the decision stays on the original request. Amber only on the count.
- **Workspace and Changes by turn** (`ui/SessionRailExtras.tsx`): the rail says whether the conversation works in the shared folder or in its own copy (with the isolation failure reason when one happened), and lists each turn's file changes with the daemon's own dry-run state (available, undone, cannot undo with the reason). Undo is **one file at a time**, confirmed in place, through the existing `file.revert`; there is no whole-turn restore and nothing is called a rollback, because a partial batch or a changed file would leave the turn half undone and nothing rewinds the agent's memory. The card says so.
- **Work log output** (`ui/ActivityDetails.tsx`, `ui/liveOutput.ts`): a running command shows the end of what the coding agent reported (last 24 lines, "Live output", the last line in the step header), full output once done. Codex streams it; Claude Code reports it when the command ends, which the step says; other agents show output only if they report progress. High-confidence keys and passwords are hidden on screen (display only) with a note. Nothing is read from a terminal.
- **PDFs, files by path** (`ui/PdfViewer.tsx`, `ui/FileReferenceChip.tsx`, `ui/fileReference.ts`): PDFs are drawn page by page by pdf.js onto a canvas (no iframe, no scripting, links and annotations not drawn), with page buttons and a "page as text" view; a PDF that cannot be drawn falls back to a card. A reply may link a project file as `[name](relative/path)` (a chip that opens the preview in a dialog) or show an image with `![alt](relative/path)`. The composer's paperclip attaches a document, audio or video file **by path**: Bitbots does not read or send its bytes, the message carries one sentence naming it, the transcript shows a chip ("sent as a path"), and a preview is offered only for files inside the project. No provider is claimed to ingest audio, video or documents.
- **Delegated questions**: a row whose teammate asked the owner a question reads "Has a question" (not "Needs approval") and says the answer goes only to that teammate; the Manager's chat shows the "Question" chip and later a plain notice that it was answered, dismissed, expired or closed, never the answer. Needs you lists the question and opens the teammate's conversation, where the existing question card is answered.
- **Assignment controls** (`DelegationGroup.tsx`): Stop (queued: Withdraw), "Stop all" through one `delegation.cancelGroup` call, and "Ask for an update", which only puts a follow-up question in the Manager's message box for the owner to send. A teammate waiting for approval appears in the Manager's chat as an "Approval" or "Question" chip (`UpdateChip`) that only opens the teammate's request.
- **Stop for assignments** (`DelegationGroup.tsx`): each active assignment row has Stop (queued: Withdraw), confirmed in place; two or more get "Stop all". **Stop and send instead** in the composer status row interrupts the running turn, waits until it has really ended, then sends the box as a fresh message.
- **Schedules** (`ui/ScheduleOverview.tsx`): read-only rows of automations and scheduled board tasks with next run, last outcome, state, time limit and a link to the last run, on the Manager settings page (everything) and as a "Schedules" card in the conversation rail (the Manager sees all; another bot sees its own and its project's).
